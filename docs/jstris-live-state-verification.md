# Jstris 상태 읽기 실측

> 이 문서는 초기 설계/조사 기록입니다. 이후 구현과 실제 스프린트 검증 결과는 [validation.md](validation.md)를 확인하세요.

2026-09-18 · Jstris v1.40.1 · Chrome · 비로그인 비공개 연습방

**결론: 현재 서비스에서 화면 인식 없이 게임 상태를 읽을 수 있다.** `Game.prototype.redraw`의 원래 동작을 호출하는 관찰용 래퍼로 `this`를 포착했다. 기존 공개 봇의 접근 방식이 현재 버전에서도 유효함을 직접 확인했다. 완성된 자동 플레이 어댑터를 검증한 것은 아니다.

대상: <https://jstris.jezevec10.com/play/practice> → `/?play=2`. 화면의 비공개 방 안내와 v1.40.1 표시를 확인했다. 게임의 보드·좌표·중력은 수정하지 않았고, 이동은 브라우저 키 입력으로만 수행했다. 검사 후 원래 `redraw`를 복원하고 임시 전역을 제거한 뒤 검증 탭을 닫았다.

## 실제로 읽힌 값

| 데이터 | 현재 런타임 경로 | 확인 결과 |
|---|---|---|
| 게임 타입 | `Game` | 전역 함수로 존재 |
| 기본 인스턴스 전역 | `window.game` | 원래는 `undefined`; 포착한 인스턴스를 별도로 보관해야 함 |
| 보드 | `game.matrix` | 20행 × 10열, 0은 빈칸. 활성 블록과 ghost는 제외 |
| 활성 블록 | `game.activeBlock` | `{id,item,pos:{x,y},rot,set}` |
| 다음 블록 | `game.queue` | 관찰 시 5개. 화면 미리보기 순서와 일치 |
| 홀드 | `game.blockInHold` | 빈 상태는 null, 홀드하면 블록 객체 |
| 홀드 사용 여부 | `game.holdUsedAlready` | 홀드 입력 후 false→true |
| 고정 블록 수 | `game.placedBlocks` | 하드드롭 후 2→3 |
| 실행 상태 | `game.starting`, `game.play`, `game.gameEnded` | 재시작 완료 후 false / true / false |
| 종류 ID | `game.blockIds` | I=0, O=1, T=2, L=3, J=4, S=5, Z=6 |

보드의 셀 값은 종류 ID가 아니다. `game.blockSets[0].blocks`에서 확인한 색상 값은 I=5, O=3, T=7, L=2, J=6, S=4, Z=1이다. 화면의 L/O/I/J 적층과 셀 값 2/3/5/6을 대조했다. 충돌 계산에는 빈칸/점유 여부를 사용하고, 색상과 종류 매핑은 분리한다.

## 입력 전후 실측

연속된 아래 4개 스냅샷은 각 키 입력 직전/직후 한 번의 런타임 평가로 필요한 필드를 복사했다.

| 단계 | 활성 블록 | x | y | rot | placedBlocks | 다음 ID |
|---|---|---:|---:|---:|---:|---|
| 입력 전 | I (0) | 3 | 0 | 0 | 2 | 4,2,6,5,5 |
| 왼쪽 키 | I (0) | 2 | 0 | 0 | 2 | 4,2,6,5,5 |
| 위쪽 키: 시계 회전 | I (0) | 2 | 0 | 1 | 2 | 4,2,6,5,5 |
| Space: 하드드롭 | J (4) | 3 | -2 | 0 | 3 | 2,6,5,5,1 |

왼쪽·회전 입력에서는 고정 보드가 변하지 않았다. 하드드롭에서 0부터 세는 x=4, y=12..15의 네 셀이 0→5로 변했다. 기존 O/L 적층은 유지됐으며, 화면에도 그 위에 세로 I 블록이 추가됐다.

별도 홀드 확인: T(id=2)에서 C를 누르자 `blockInHold.id=2`, `holdUsedAlready=true`가 됐고, 다음 큐 첫 블록 Z(id=6)가 활성 블록이 됐다. 보드와 `placedBlocks=4`는 유지됐다.

F4 재시작 확인: 같은 게임 인스턴스가 유지됐다. 준비 화면 직후에는 이전 보드와 카운터가 잠시 남아 있었다. 이후 실행 상태에서 보드가 전부 0, `placedBlocks=0`, 홀드 null, `holdUsedAlready=false`로 초기화됐다. **재시작을 인스턴스 교체로 감지하거나 `gameEnded=false`만으로 실행 가능 상태를 판단하면 안 된다.**

## 어댑터 설계에 반영할 점

1. `redraw`는 인스턴스를 잡는 수단이다. 호출 수를 프레임 수나 블록 생성 번호로 취급하지 않는다.
2. 상태 읽기는 모델 호출과 분리한다. 읽은 값을 복사해 모델에 전달하고, 키 입력 직전에 다시 확인한다.
3. 재시작/준비/실행 상태를 구분하고 재시작마다 자체 gameEpoch를 증가시킨다. 같은 종류의 연속 블록과 홀드 전환도 구분할 별도 이벤트 계약이 필요하다.
4. 활성 블록은 스폰 직후 y=-2가 관찰됐다. 20행 보드에 활성 블록을 억지로 합치지 않는다. 숨겨진 고정 셀·top-out 동작은 아직 검증하지 않았다.

## 남은 검증

줄 삭제, 높은 적층/top-out, 벽·바닥 회전 킥, 줄 삭제 중 입력, 모드 전환, 안정적인 spawn/lock 구분, 입력 최소 간격은 미검증이다. 40줄 스프린트와 Jev API를 연결한 완주도 아직 수행하지 않았다. 따라서 개발 스펙의 M0는 기본 접근 경로와 입력 연동을 확인한 상태이며, 전체 완료는 아니다.
